# Key Management Design for Roadmap Integrity

**Task:** git-integration-5-task-013
**Status:** Design Document
**Created:** 2025-12-10

---

## Overview

This document specifies the cryptographic key management system for signing activity log entries. Signed entries provide non-repudiation and authenticity verification for roadmap changes.

## Goals

1. **Non-repudiation** - Prove who made each roadmap change
2. **Authenticity** - Verify changes were made by authorized team members
3. **Simplicity** - Easy setup for developers (single command)
4. **Security** - Private keys never committed to repository
5. **Team Support** - Multiple authorized signers per project

## Design Decisions

### Algorithm: Ed25519

**Why Ed25519:**
- Fast signing and verification
- Small keys (32 bytes) and signatures (64 bytes)
- Secure against timing attacks
- Widely supported (SSH, GPG, libsodium)
- No patents or licensing issues

**Alternative Considered:** ECDSA (secp256k1)
- Larger signatures
- More complex implementation
- Bitcoin association may confuse users

### Key Storage

```
~/.vibey/                          # User's home directory
├── private.key                    # Ed25519 private key (never committed)
├── public.key                     # Ed25519 public key (for convenience)
└── identity.txt                   # User identity (name, email)

.vibey/                            # Repository (committed)
└── authorized-signers/
    ├── alice@example.com.pub      # Public key for Alice
    ├── bob@example.com.pub        # Public key for Bob
    └── manifest.yaml              # Signer metadata
```

### Private Key Format

```
# ~/.vibey/private.key
# Ed25519 Private Key - DO NOT SHARE
# Generated by: vibey auth setup
# Identity: alice@example.com
-----BEGIN VIBEY PRIVATE KEY-----
<base64-encoded 64-byte Ed25519 private key>
-----END VIBEY PRIVATE KEY-----
```

### Public Key Format

```
# .vibey/authorized-signers/alice@example.com.pub
# Authorized Signer: Alice Smith
# Added: 2025-12-10T15:30:00Z
# Added by: alice@example.com (self)
vibey-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAIGBLkT... alice@example.com
```

### Signer Manifest

```yaml
# .vibey/authorized-signers/manifest.yaml
version: "1.0"
created: "2025-12-10T15:30:00Z"
updated: "2025-12-10T16:00:00Z"

  - identity: alice@example.com
    name: Alice Smith
    added: "2025-12-10T15:30:00Z"

    active: true

  - identity: bob@example.com

    added: "2025-12-10T16:00:00Z"
    added_by: alice@example.com
    role: developer
    active: true
```

## Signing Flow

### Activity Log Entry Signing

```python
def sign_activity_event(event: CommandActivityEvent, private_key: bytes) -> str:
    """Sign an activity log event."""
    # 1. Serialize to canonical form (deterministic)
    canonical = canonicalize_event(event)

    # 2. Sign with Ed25519
    signature = ed25519_sign(private_key, canonical)

    # 3. Return base64-encoded signature
    return base64.b64encode(signature).decode('utf-8')

def canonicalize_event(event: CommandActivityEvent) -> bytes:
    """Create canonical (deterministic) serialization for signing."""
    # Include only fields that matter for verification
    signed_data = {
        "id": event.id,
        "timestamp": event.timestamp,
        "command": event.command,
        "object_type": event.object_type,
        "object_id": event.object_id,
        "changes": sorted(event.changes, key=lambda c: c.field),
        "file_path": event.file_path,
        "file_hash_after": event.file_hash_after,
    }
    # JSON with sorted keys, no whitespace
    return json.dumps(signed_data, sort_keys=True, separators=(',', ':')).encode('utf-8')
```

## Verification Flow

```python
def verify_activity_event(event: CommandActivityEvent, authorized_signers: dict) -> VerificationResult:
    """Verify an activity log event's signature."""

    # 1. Check if signed
    if not event.signature:
        return VerificationResult(
            verified=True,
            signed=False,
            message="Unsigned entry (acceptable)"
        )

    # 2. Check signer is authorized
    if event.signer not in authorized_signers:
        return VerificationResult(
            verified=False,
            signed=True,
            message=f"Unknown signer: {event.signer}"
        )

    # 3. Get signer's public key
    public_key = authorized_signers[event.signer]

    # 4. Verify signature
    canonical = canonicalize_event(event)
    signature = base64.b64decode(event.signature)

    if not ed25519_verify(public_key, canonical, signature):
        return VerificationResult(
            verified=False,
            signed=True,
            message="Invalid signature"
        )

    return VerificationResult(
        verified=True,
        signed=True,
        signer=event.signer,
        message=f"Verified: signed by {event.signer}"
    )
```

## Security Considerations

### Private Key Protection

1. **File Permissions:** Private key file has mode 0600 (user read/write only)
2. **Location:** `~/.vibey/` is outside repository
3. **gitignore:** Add `~/.vibey/` to global gitignore
4. **Warning:** CLI warns if private key permissions are too open

### Trust Model

1. **First Signer:** Self-authorizes (bootstrap problem)
2. **Subsequent Signers:** Must be added by existing authorized signer
3. **Revocation:** Set `active: false` in manifest (not cryptographic revocation)
4. **Key Rotation:** Add new key, mark old as inactive

### Attack Scenarios

| Attack | Mitigation |
|--------|------------|
| Stolen private key | User must rotate key, revoke old |
| Unauthorized signer | Only authorized signers in manifest |
| Tampered manifest | Manifest is version controlled, review in PRs |
| Replay attack | Event ID (ULID) prevents replay |
| Man-in-middle | Direct file hash verification |

### What Signing Does NOT Protect Against

1. **Authorized malicious user** - An authorized signer can still make bad changes
2. **Compromised machine** - If attacker has access to private key
3. **Social engineering** - Owner adds unauthorized person

Signing proves *who* made a change, not *whether* the change is correct.

### `vibey auth setup`

Generate keypair and configure identity.

```bash
$ vibey auth setup
Generating Ed25519 keypair...
✓ Private key saved to: ~/.vibey/private.key (mode 0600)
✓ Public key saved to: ~/.vibey/public.key

Enter your identity (email): alice@example.com
Enter your name: Alice Smith
✓ Identity saved to: ~/.vibey/identity.txt

Your public key (share this for authorization):
vibey-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAIGBLkT... alice@example.com
```

### `vibey auth init-project`

Initialize signing for a project (first signer).

```bash
$ vibey auth init-project
Initializing roadmap signing for this project...
✓ Created .vibey/authorized-signers/
✓ Added alice@example.com as owner

Commit and push to enable signed changes.
```

### `vibey auth add-signer`

Add an authorized signer.

```bash
$ vibey auth add-signer bob@example.com "Bob Jones" "vibey-ed25519 AAAA..."
Adding authorized signer...
✓ Created .vibey/authorized-signers/bob@example.com.pub
✓ Updated manifest.yaml

Commit and push to authorize bob@example.com.
```

### `vibey auth list`

List authorized signers.

```bash
$ vibey auth list
Authorized Signers:
  alice@example.com (Alice Smith) - owner - active
  bob@example.com (Bob Jones) - developer - active
```

### `vibey auth export`

Export public key for sharing.

```bash
$ vibey auth export
Your public key:
vibey-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAIGBLkT... alice@example.com

Share this with a project owner to be authorized.
```

### `vibey auth revoke`

Revoke a signer's authorization.

```bash
$ vibey auth revoke bob@example.com
Revoking authorization for bob@example.com...
✓ Marked bob@example.com as inactive in manifest

Note: Revocation is soft. Existing signed entries remain valid.
Commit and push to apply revocation.
```

## Migration Path

### Existing Activity Logs

Existing unsigned entries remain valid. Verification treats unsigned entries as acceptable:

```python
if not entry.signature:
    # Unsigned = OK (legacy or signing not enabled)
    return VerificationResult(verified=True, signed=False)
```

### Enabling Signing

Signing is enabled when:
1. User has `~/.vibey/private.key`
2. Project has `.vibey/authorized-signers/`

Until both exist, entries are logged without signatures.
